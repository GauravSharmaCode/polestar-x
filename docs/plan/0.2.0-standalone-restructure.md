# PoleStar-X 0.2.0 — Standalone, Stable, Pinned

> Plan to fix the structural issues from the 0.1.x line and ship a stable, dependable 0.2.0.

## Context

PoleStar-X currently lives as a fork of the entire `pi-mono` repo. The published 0.1.0 was unreleasable (missing runtime deps); 0.1.1 patched the dep manifest but the architectural issues remain:

1. **Repo carries a full fork of pi** (`packages/coding-agent`, `packages/agent`, `packages/ai`, `packages/tui`, `packages/harness`) that is not consumed by the published package — npm-installed `@earendil-works/pi-*` is what actually runs.
2. **`POLESTAR_APP_PACKAGE_DIR` env var** is set in `cli.ts` but the upstream pi 0.78.1/0.79.3 packages do NOT contain the code that reads it. It only exists in the local fork at `packages/coding-agent/src/config.ts`. So in any global install, that env var is a no-op. The "PoleStar-X" branding users see in the TUI comes entirely from the extension's `ctx.ui.setHeader()`.
3. **No release smoke test gate** — 0.1.0 shipped with imports that didn't resolve because nothing tested the published tarball end-to-end.

## Goals

- Standalone repo: one package, no forked pi internals.
- All features from 0.1.0 and 0.1.1 preserved.
- Pinned pi dependency with a manual upgrade gate (no auto-tracking, no broken-release consumption).
- Real install/run smoke test gate before publish.

## Constraints

- Cannot afford fresh Anthropic / Gemini API keys for testing.
- Must use existing pi auth (`github-copilot`, `opencode`, `opencode-go`).
- 0.2.0 must be fully stable and smoke-tested before release.

## Locked Decisions (Phase 0)

| Decision | Choice |
|---|---|
| Repo strategy | Gut the existing `polestar-x` repo. Keep git history, GitHub URL, issues, stars. Delete all forked `packages/` except `packages/polestar/`. Flatten to a single-package repo at root. |
| Pi version target | Exact pin `0.79.3` for all `@earendil-works/pi-*`. No `^`, no `~`. |
| pi-memory | Stay exact-pinned to `1.0.0` for 0.2.0. Bump later in 0.2.x. |
| CLI architecture | Keep `main()` + `extensionFactories` (it IS public API, IS supported). Drop `POLESTAR_APP_PACKAGE_DIR`. |
| Branding | Lives in the extension (`ctx.ui.setHeader`, status indicators, `/init-config` scaffolding) **and** in sovereign identity (see below). |
| Config dir | Project-local: `.polestar/`. **REVISED 2026-06-14:** user config moves to `~/.polestar/agent/` (full sovereignty) instead of staying at `~/.pi/agent/`. A one-time migration in `cli.ts` copies `~/.pi/agent → ~/.polestar/agent` so upgrading 0.1.x users keep auth/sessions/settings. See "Sovereign identity" below. |
| Sovereign identity (NEW 2026-06-14) | `cli.ts` sets `PI_PACKAGE_DIR` to polestar's package root **in the published layout only** (no `src/`), so pi reads polestar's `package.json` + `CHANGELOG.md`: `APP_NAME=polestar`, config dir `.polestar`, version is polestar's, and the startup "What's New" is polestar's — not pi's. pi resolves bundled assets relative to that root, so the build vendors pi's `theme/`, `export-html/`, and interactive `assets/` into `dist/` (`scripts/vendor-pi-assets.mjs`). Source-checkout runs (`src/` present) skip the redirect and keep pi's identity to avoid pi's `src`-vs-`dist` asset heuristic missing the vendored files. The smoke asserts `--version == package version` to prove sovereignty end-to-end. |
| Smoke providers | `github-copilot` and `opencode` from existing `~/.pi/agent/auth.json`. |

### Pi version review

Pi 0.78.1 → 0.79.3 delta:
- No breaking changes in `ExtensionAPI`, `createAgentSessionRuntime`, or `main`.
- Relevant fix in 0.78.1: "SDK embedding in bundled Node apps failing with ENOENT" — affects global-install scenarios.
- Additive in 0.79.0: `project_trust` extension event, `ctx.isProjectTrusted()`, `ctx.mode` — optional adoption, useful for think/plan/spec security modes.
- Additive in 0.79.1: `defaultProjectTrust` setting, extension autocomplete trigger chars.
- Additive in 0.79.2/0.79.3: provider fixes and metadata corrections.

Verdict: safe to upgrade. Probably desirable.

## Phase 2 — Repo restructure

On a fresh branch `chore/standalone-0.2.0`:

1. Move `packages/polestar/src/**` → `src/**` (root).
2. Move `packages/polestar/CHANGELOG.md`, `README.md`, `LICENSE`, `NOTICE.md`, `tsconfig.build.json`, `vitest.config.ts` → root.
3. Replace root `package.json` with the polestar one (no `workspaces`; `bin`/`main`/`types` point at root `dist/`).
4. Delete:
   - `packages/coding-agent/`
   - `packages/agent/`
   - `packages/ai/`
   - `packages/tui/`
   - `packages/harness/`
   - root scripts that managed pi-mono: `release.mjs`, `generate-coding-agent-shrinkwrap.mjs`, `sync-versions.js`, `local-release.mjs`, `build-binaries.sh`, etc.
   - root `tsconfig.base.json` (collapse into root `tsconfig.json` and `tsconfig.build.json`)
   - `.github/workflows/openclaw-gate.yml`, `.github/workflows/build-binaries.yml`, `.github/workflows/cd.yml` (replace later with polestar-specific CI)
   - `.pi/extensions/`, `pi-test.sh|bat|ps1`, `test.sh`
5. Keep & port to root `scripts/`:
   - `check-package-import-deps.mjs` (already proven, the 0.1.1 fix)
   - `publish-polestar.mjs` → rename to `release.mjs`

End state: flat repo, one `package.json`, no workspaces, no forked source.

## Phase 4 — Test gates

Write these BEFORE Phase 3 changes — they're the safety net for the restructure.

### 4a. Port `scripts/check-package-import-deps.mjs`

Already exists in `packages/polestar`. Bring it to root. Runs in `prepublishOnly`. Scans `dist/**/*.js` for `import`/`require`, asserts every external package is in `dependencies` or `optionalDependencies`. This is the 0.1.0 → 0.1.1 fix; keep it.

### 4b. `scripts/smoke.sh` — full install smoke test (new)

```bash
#!/usr/bin/env bash
set -euo pipefail
PKG_DIR="$(pwd)"
TARBALL=$(npm pack --silent)
SMOKE_DIR=$(mktemp -d)
cd "$SMOKE_DIR"
npm install -g --ignore-scripts "$PKG_DIR/$TARBALL"

# Gate 1: process boots, deps resolve
polestar --help > /dev/null
polestar --version
polestar --list-models > /dev/null

# Gate 2: real prompt with existing free providers
polestar --model github-copilot/gpt-4o-mini -p "Say exactly: ok" | grep -q "ok"
polestar --model opencode/grok-code -p "Say exactly: ok" | grep -q "ok"

# Gate 3: interactive mode boots (tmux, type prompt, wait for reply, quit)
tmux new-session -d -s polestar-smoke -x 120 -y 40 \
  "polestar --model github-copilot/gpt-4o-mini"
sleep 3
tmux send-keys -t polestar-smoke "Say exactly: ok" Enter
sleep 15
tmux capture-pane -t polestar-smoke -p | grep -q "ok"
tmux send-keys -t polestar-smoke "/quit" Enter
tmux kill-session -t polestar-smoke 2>/dev/null || true

# Gate 4: PoleStar-specific features
polestar --model github-copilot/gpt-4o-mini -p "/init-config" > /dev/null
test -d .polestar
test -f .polestar/settings.json
test -f .polestar/mcp.json

npm uninstall -g @gauravsharmacode/polestar-x
rm -rf "$SMOKE_DIR"
echo "SMOKE PASS"
```

### 4c. `scripts/check-pi-upgrade.mjs` — future-proofing (new)

```bash
node scripts/check-pi-upgrade.mjs 0.80.0
```

It:
1. Creates a temp branch.
2. Pins the new pi version in `package.json`.
3. Runs `npm install`, build, unit tests, full smoke.
4. Reports pass/fail with diff.
5. **Does not commit.** You decide whether to merge.

This is the answer to "I don't want to track every pi version bump" and "I don't want to import broken pi releases" — you upgrade when you want, with confidence.

### 4d. Keep existing unit tests

`vitest --run` continues to cover routing, self-heal, think-write, compose-system-prompt, tools. These already exist in `packages/polestar/src/**/*.test.ts`. Port as-is to `src/**/*.test.ts`.

## Phase 5 — Release pipeline

`scripts/release.mjs` enforces this sequence — refuses to publish if anything fails:

1. Working tree clean check
2. `npm ci --ignore-scripts`
3. `npm run build`
4. `vitest --run` (unit)
5. `node scripts/check-package-import-deps.mjs`
6. `npm pack`
7. `./scripts/smoke.sh` against the packed tarball
8. Bump version in `package.json` + `CHANGELOG.md`
9. `git commit -am "Release v0.2.0"` + `git tag v0.2.0`
10. `npm publish` (no `--ignore-scripts` so `prepublishOnly` is a second safety net)
11. `git push --follow-tags`
12. **Post-publish**: re-run `./scripts/smoke.sh` against `npm install -g @gauravsharmacode/polestar-x@0.2.0` from the real registry.

Step 12 is the gate 0.1.0 was missing. Without it, you cannot tell a registry-shipped tarball from a local-pack tarball, which is exactly how 0.1.0 reached users broken.

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| Pi 0.79.3 has subtle extension API drift breaking a hook | Low | Type-check after dep bump; smoke catches behavior break |
| Removing pi-mono breaks an import we forgot | Medium | `check-package-import-deps.mjs` catches at build; smoke catches at runtime |
| Lose a 0.1.x feature in restructure | Medium | Feature checklist in Phase 1; each item verified by smoke or unit test in Phase 4 |
| Global install on Windows breaks again | Medium | Phase 4b smoke runs `npm install -g` on the actual machine publishing |
| Provider drift breaks smoke (Copilot rate limit, OpenCode endpoint change) | Low | Smoke uses graceful fallback for provider gates; `--list-models` still gates |
| Users on 0.1.x lose sessions | Very low | Sessions stay at `~/.pi/agent/sessions/`; no migration needed |
